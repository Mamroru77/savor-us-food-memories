# Savor · Tab 真机抽动排查：首轮减负

日期：2026-09-16

## 本轮改动

仅修改 TabBar 发布逻辑，不修改五个按钮的图形、WXML、CSS、Morphicons 移植引擎、SVG 帧生成、480ms 动画时长或 `wx.switchTab` 点击逻辑。

1. 相同主题、Quiet 和标签等外观重复同步时，不再发布新的 Tab 视图版本。
2. 仅文字标签改变时，保留五个相同图标命令的版本，避免无关更新干扰正在提交的 SVG 帧。
3. 真正进入页面仍强制发送唤醒命令。这一轮没有简单地屏蔽 `onShow`，避免从二级页面或原生界面返回后缓存图标停住。
4. 带提交回调的调用仍等待原来的视图确认，不提前执行回调。

立即切页、原有形状变形、Quiet 和主题切换保留；没有提前点亮目标 Tab、隐藏图标、叠加缩放位移，或用淡入淡出掩盖问题。

## 已取得证据

- 同一模拟器回忆页，连续 10 次相同外观更新：Tab 容器 `setData` **10 → 0 次**，视图版本不再改变。这是提交次数，不是硬件绘制次数或手机帧率。
- 新增 **7 项**回归，覆盖重复外观、仅标签改变、主题/Quiet、真实页面重入、即时导航、回调顺序、待提交帧版本稳定性。
- 完整 `verify:all` 通过，最终退出码 0，用时 43,234 ms。
- 官方原生 WXML / WXSS 编译成功。
- 等待真实路由稳定后，模拟器中的地图、记录、回忆切换选中状态正确，三次检查图标 fallback 均为 0。
- 先前固定等待 850ms 的五 Tab 采样读取到尚未完成切换的旧路由，**不计为五 Tab 全链路通过**；没有据此修改导航逻辑。

## 尚未证明

这只消除了一类确定存在的冗余更新，**尚未证明它是真机抽动的唯一根因，也没有完成真机验收**。

SVG 帧图片到最终静态图标的原生解码/合成交接仍是后续排查对象，本轮未贸然重写或替换渲染器。模拟器流畅不能替代手机逐帧证据。
