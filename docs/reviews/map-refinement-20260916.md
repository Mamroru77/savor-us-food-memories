## 分组一：缩放状态转换 — 保留

### 1. P1：未发生分组变化，也会强制收起堆叠

旧 `readMapScale` 对超过 0.05 的缩放变化无条件执行收起和标记重建。

修正后：
- 分组代表及成员均未变：只更新缩放状态，保留原生标记／照片／展开进度和分页。
- 远处分组发生拆分，但当前展开组未变：不打断当前堆叠。
- 当前组确实拆分：仍关闭失效的堆叠并重建，过期缩放回调仍被忽略。

证据：同一真实分组的原生受控缩放回放中，修改前稳定后 `open:false`，修改后 `open:true`；分组尺寸均为 `[1,2,1,1]`。另外将真实分组聚焦到画面内，展开后重复回放，仍保留一行展开项。

**边界：这是原生页面中的受控事件回放，不是新的真机双指缩放手感验收。** 最初未校准原生缩放值的回放受相机状态变化影响，未作为最终同状态对照。

### 2. P0：从堆叠拆为单点时，图标可能消失

旧实现把堆叠使用的透明 `stack-anchor.png` 和 1px 宽度继续当成单点图标的来源。原生校准到缩放 18 后的截图可见选中点消失。

修正后只继承旧单点的图标与尺寸；堆叠转单点时恢复正常图标／回退图标，不继承透明锚点或从 1px 开始放大。原生状态确认所有单点 `transparentAnchor:false`；真实堆叠仍保留必要的透明锚点，未破坏其原生 callout。

## 分组二：真实照片辨认 — 保留

### 3. P1：身份恢复后，照片画布错过初始化

原生页面已经 `active:true / identityReady:true`，但 `hasStoredCanvas:false / hasRenderer:false`。Canvas 在身份门禁解除后才挂载，而初始化只在 `onReady` 查询一次。

通过现有页面方法补跑初始化后，画布与 renderer 均恢复，原生截图出现已有餐厅照片，证明不需要替换图片或改图标风格。

正式修正：
- 在 Map 视图更新完成后补充受保护的画布初始化。
- 同时最多一个查询；已经初始化则不重复创建。
- 隐藏页面使旧请求失效，过期回调不能替换新画布。
- 画布到达后只增强当前照片，不重新分组，不再次移动相机。

重新编译、冷启动后原生确认 `renderer:true`，已有餐厅照片正常显示。没有照片的记录仍使用原有占位，不为好看强塞示例图片。
