# Map 堆叠：视频分析与本轮修正

2026-09-16 · 针对用户提供的 `VID_1.mp4`，不重新设计 Map。

## 读取与证据

已恢复原有 Windows 工具连接。文件实际位于项目目录内，大小 1,725,441 字节；通过工具私下读取并校验 SHA-256，没有上传 GitHub。视频流为 1166×2560、60fps、148 帧，约 2.47 秒。**片段只有展开，没有收起过程**，不能据此替用户判定收起体验。

逐帧结果：
- 约 0.533 秒，箭头切换方向。
- 约 0.567–0.833 秒，底部根图标发生下移后回弹，而地图和底部详情卡没有相同位移。
- 对餐食图案做模板跟踪，根图标最大下偏约 **36 个原始视频像素**，随后回到起点；这是录屏像素，不是 CSS px。
- 上方展开项有连续数帧保持同一姿态、随后跳到下一位置的表现。视频编码 60fps，不代表小程序动画实际以 60fps 渲染。

## 本批修改

### 1. 按钮更靠近图标

单页堆叠的箭头下移 **8 个原生布局 px**；本轮开发者工具截图中约为 10 个图像像素。点击区域同步校正，保留至少 44px 宽、40px 高，不压入根图标的点击区域。

有分页的堆叠仍保留原有按钮间距，避免挤占分页控件。本次没有通过缩小触控区域制造视觉紧凑。

### 2. 原生容器固定边界

旧路径每帧同时调整气泡高度和根图标内部位置。逻辑上两者抵消，但原生布局若分阶段呈现，就可能让根图标先偏移再归位。

本批保留原有 320ms 逻辑帧、曲线、单帧确认与中断保护，仅将可见原生内容投影到**固定高度的气泡容器**：
- 根图标内部位置固定，不再跟随逐帧容器伸缩补偿。
- 展开项和顶部控件继续沿原有逻辑路径运动。
- 透明点击层保留原有逻辑帧；原生可见内容的固定容器投影与它逐点等价。
- 多页组按完整页容量预留边界，最后一页较短也不改变根位置。
- 不改餐厅坐标、相机、腾讯底图、Tab 或保存数据。

固定边界可能增加收起状态的透明容器面积；没有额外挂载收起项的照片，也不宣称它降低内存占用。

## 验证与决定

- 本地及远程 `verify:map-motion`：**23/23 通过**。原有 19 项断言逐字保留，新增固定边界、路径等价、点击层同步及按钮间距 4 项。
- 开发者工具原生前后回放均完成展开、收起、展开中反向；最终校准到原生缩放 18 的稳定真实双项组，各 12 次调用全部成功，最后恢复原选中记录及收起状态。
- 修改后原生运行数据：动画全过程容器高 230px、根位置 141px 固定，逻辑进度仍正常变化；真实照片正常显示。
- 原生截图确认按钮下移，收起与展开端点的根图标位置一致。
- 首次编译后立即调用自动化出现一次响应超时；待页面恢复后重放成功。失败记录保留，不算入成功批次。
- 尝试 GDI 窗口录屏只得到无有效内容的画面，**不作为修改后运动影像证据**。本次有效视觉证据是用户原视频和原生截图，运行数据不能替代新的真机录像。
- 最终 `verify:all`：**exit 0，43155ms**，包括 Map 保存及相关 UI 检查。
- 全量验证曾拦截 Map WXML 新哈希、审查记录的基线哈希笔误，以及共享帧字段约束。已修正登记笔误，并收敛为原有逻辑帧／点击层与原生固定容器的等价投影；没有删除旧断言。只为 Map WXML 登记独立的精确哈希审查，历史 fixture 未改。
- 一次重新编译后的试跑选中了会在缩放 18 拆分的组，返回 `No selected stack`，未算作通过。最终前后回放均在原生缩放 18 选用稳定的同一真实双项组，完整验证展开、收起及中途反向。
- 有效原生证据：`video-stable-before/` 与 `video-stable-after/`；旧试跑保留但不替代最终结果。

**决定：保留本批按钮间距及固定原生边界修正；不宣布全部“卡壳”已消除。**

## 明确未收口

1. 同状态原生受控回放的展开帧提交间隔中位数，修改前后均约 **46ms**。本批保留回调确认后再调度的保护，没有证据宣称达到 60fps；整体帧节奏仍需继续处理。下一项候选是保留“最多一帧在途”，只补足目标帧间隔，而非每次确认后再完整等待 16ms；需要单独审查时序契约和验证，未在本批顺手改动。
2. 在地图上方空间不足的场景，展开项和顶部按钮仍可能进入搜索区域。下移 8px 不能替代完整的遮挡处理。
3. 用户此前确认的真机等验收不自动覆盖新 Map 改动。本批不把开发者工具回放写成新的真机手感验收。
