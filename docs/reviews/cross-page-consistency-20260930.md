## 2. Selected GLOBAL-P0 issues

* **GLOBAL-P0-1 — the identity / loading state is localized on three tabs and hardcoded on two.**
  `Home`, `Us` and `Me` render `{{copy.s691f4302fc}}`; `Map` rendered a hardcoded `正在验证...` and `Add`
  fell back to the same hardcoded literal when `identityLabels` was not yet set. In the English locale
  the same state therefore showed English on three tabs and Chinese on two.
* **GLOBAL-P0-2 — Map's selected-place photo had no image-failure path.** `Add`, `Home`, `Us` and `Me`
  all route dynamic photos through the shared `data-source` + `binderror="onImageError"` + `imageErrors`
  fallback (`utils/uiFeedback.js`). Map's `.place-photo` had none, so a failed photo stayed broken.
* **GLOBAL-P0-3 — Add's `原图` was the only user-facing string in the five tabs with no locale path.**
  Every other visible string resolves through the catalog; `{{originalMode ? '原图' : ''}}` did not.

Three genuine cross-page inconsistencies; nothing manufactured. The bilingual inline ternaries
(Add's rating-clear label, Us's "Manage shared space & wishlist") produce correct output in **both**
locales, so they are a pattern divergence rather than a user-visible defect and are recorded in §5
rather than changed.

## 5. Localization result

* Every identity/loading pill on all five tabs now resolves through the catalog — **5/5 consistent**.
* `原图` now has a catalog entry (`sc0a8060f3b`) instead of a Chinese-only literal.
* Remaining **pattern** divergences, recorded and **not** changed because their output is correct in
  both locales: Add's rating-clear label
  (`locale === 'zh-CN' ? '已评 N 星 · 清除评分' : 'N stars · Clear rating'`) and Us's
  `{{locale === 'zh-CN' ? '管理双人空间与 Wishlist' : 'Manage shared space & wishlist'}}`.
  Both are bilingual inline ternaries rather than catalog lookups; normalizing them would add two
  catalog entries and reopen two frozen pages for no user-visible change.
* No new translation system; the existing TSV → `build:locales` path was used.

## 6. Image-fallback result

Product-wide, every `<image>` now either (a) routes a dynamic source through the shared
`imageErrors` + `binderror="onImageError"` contract, (b) uses a deliberate static fallback
(`/images/alex.jpg`, the Add ambient photo which is intentionally `ambient-stable` and exempt in
`verify-ui-quality`), or (c) is a generated asset that cannot fail (Me's `chartUri` SVG data URI, Map's
composed marker/stack PNGs and native `<cover-image>` chevrons, which the native map API requires as
file paths).

## 7. Icon-system result

One family end to end: Lucide SVGs through `utils/icons.js` / the Morphicons registry, `stroke="1.75"`
everywhere, PEARL/DUSK colours from the same tokens. **No bitmap icons exist in the product UI.** The
only PNGs are (a) Map's `<cover-image>` marker chevrons — `<cover-image>` cannot render an inline SVG
data URI, so a file path is mandatory — and (b) the runtime-composed marker/stack assets, which are
generated bitmaps by design. `verify-icons.cjs` keeps asserting the registry, the alias coverage, the
generator's byte-stability and the Map POI toggle's two glyphs.

## 8. State-language result

The identity/loading state now reads the same on all five tabs. Other equivalent states were already
consistent: `empty` uses the shared `.empty-state` voice, `error` uses `map-fallback` / inline
`helper-note` copy from the catalog, `locked`/verifying redacts identically, and Quiet removes
interpolation uniformly. Interaction availability during loading is unchanged on every tab.

## 9. Responsive / accessibility result

No responsive contract was contradicted or needed adding. Hit targets and labels were already
consistent (88 rpx floating controls and row/heart targets; `aria-role` + `aria-label` on every
interactive view; colour-independent state on the Map POI toggle, the Add rating and the like buttons).
