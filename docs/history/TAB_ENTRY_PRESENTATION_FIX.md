# Tab 缓存页首帧回跳补修

日期：2026-09-13  
基线：9117569；用户确认该版仍有“目标态 → 旧态 → 目标态”的回跳。

## 上轮没有覆盖的情况

上轮解决了同一 entry 被 observer / replay 重启的问题，但静态 fallback 仍优先读取组件上次保存的 `staticName`。缓存的 Us 页里，Add 上次通常处于非选中态，因此开播前可能先露出竖直餐具，随后形变才从交叉餐具起步。

对实际 9117569 WXML 表达式做源码级复现：在本次起点为 utensils-crossed、目标为 utensils、缓存静态值为 utensils 的条件下，旧表达式返回 utensils；新表达式返回本次起点 utensils-crossed。其余四组同样验证。证据见 `reports/tab-entry-presentation-reproduction.json`。

这不是原始视频逐帧分析。本轮只有用户上传的分析截图及“最新包仍有问题”的确认，没有收到 MP4。

## 本轮修改（仅四个运行时文件）

1. **导航前准备缓存实例**：TabBar 使用不持久化的实例集合，在 wx.switchTab 前给已挂载实例提交本次目标、起点、entry，并暂停开播；detached 删除引用。没有等待整段动画或修改页面业务。
2. **待播态只显示本次起点**：静态图案以本次 entry 是否完成为依据，而不是直接复用缓存页上次的 staticName。动画完成才允许显示精确目标端点。
3. **明确开播阶段**：仅目的页面 onShow 提交完成后激活 entry；暂停期间不生成运动帧、不运行动画计时器。重复生命周期不把已激活的同一 entry 重新暂停。
4. **首挂载门控**：新实例尚无原生路由/明确页面选中状态时，不先挂载默认 Home 那套图标。状态准备后一次挂载；此后缓存实例不会为播放动画反复隐藏整个 TabBar。
5. **降级与异常**：Quiet 和 SVG 永久降级直接显示目标；导航失败恢复源选中态；完成回调使用运动启动时捕获的 entry，避免将新 entry 错标为完成。

运行时修改限于：
- `custom-tab-bar/index.js`
- `custom-tab-bar/index.wxml`
- `components/morph-icon/index.js`
- `components/morph-icon/index.wxml`
