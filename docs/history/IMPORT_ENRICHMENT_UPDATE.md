# 通用导入第一阶段：类别与具体分店

> 已被 [免费优先调整](FREE_FIRST_UPDATE.md) 部分取代：默认关闭云端商家搜索，不需要升级套餐或配置超过 6 秒的函数超时。以下保留上一版本设计及部署记录，不作为当前默认部署步骤。

日期：2026-09-11。此更新需要客户端和云函数一起更新，不是仅前端的 Map D 更新。

## 已实现

- Add：粘贴分享文本 → 提取候选 → 可选腾讯城市内分店搜索或原生选点 → 核对分店及地址 → 确认进入草稿。不会自动保存食记。
- 菜系与餐饮类型分开。明确的“西餐”“韩国料理”可归类；“火锅自助”只提取火锅、自助餐，不据此认定中餐。保存原始类别及来源。
- 店名带“寿喜烧”“嘎抛”等只生成待采纳建议，不冒充平台事实。用户可编辑菜系、切换餐饮类型，保存后也可修改。
- 腾讯 POI 类别仅作为缺失类别的补充，不自动覆盖分享文本或用户已确认的类别。搜索结果是腾讯地图资料，不是大众点评／美团认证资料。
- 必须显式确认具体分店；名字不同会提示核对。改店名、城市、来源、分享文本或取消，会使旧搜索结果失效。
- 只保留用户确认的坐标和腾讯 POI ID。个人照片、笔记、评分和花费不会被商家资料覆盖；导入会清空实际用餐日期，待用户填写。
- Map D 不变：标记不重复显示店名，底卡／收起条保留店名，聚合数量、方图、卡片尺寸及动画不变。底卡分类行改用真实菜系和餐饮类型，缺失时显示“尚未记录类别”，不再套用默认小馆。

## 必须执行的部署

1. 保持原 CloudBase 环境 `cloud1-d9gqm52id66c0bcda`，先部署更新后的 `mealRecords`（上传并部署，云端安装依赖）。否则新类别字段可能被旧函数忽略，新的搜索坐标来源也可能不被接受。
2. 在腾讯位置服务控制台取得有 WebService 地点搜索权限的 Key；确认服务权限、额度、预算与使用条款。此代码未实现 SK 签名，不要将“仅 Key”实现当作支持已启用 SK 校验的配置。
3. 部署新增的 `placeLookup`，云端安装依赖，并在该函数服务端环境变量设置：
   - `TENCENT_MAP_KEY`：腾讯地图 Key。
   - `PLACE_LOOKUP_ALLOWED_OPENIDS`：允许使用搜索的私人账号 OPENID，多个用英文逗号分隔。身份由 SDK `getWXContext()` 获取，不信任前端传入身份。可由有权限的云端管理员核对现有记录的 `createdBy`；不要把私人身份列表或 Key 写入客户端、仓库或公开截图。
4. 将函数执行超时设为大于 6 秒（例如 10 秒），确认云函数能访问腾讯固定 HTTPS 接口。配置腾讯配额／预算监控；本代码不保证服务免费。
5. 再编译／发布新版小程序，按下面步骤真机验收。无需清空原缓存或重建食记。

没有 Key、没有白名单、账号不在白名单、配额／网络失败时，会给出可诊断错误，保留候选并允许使用原生选点。原生选点自身仍需要微信定位权限及相关配置，不提供商家类别或照片。

## 后端边界

固定请求 `https://apis.map.qq.com/ws/place/v1/search`，使用 `region(city,0)`，不自动扩大城市范围；每次最多 10 个候选。关键词和城市有输入限制，响应上限 512 KiB，绝对请求期限 6 秒，不跟随重定向，不接受任意 URL，不抓网页／图片，不写数据库。错误不回传 Key、原始上游错误或响应正文。

1500ms 冷却仅对同一温实例内的账号有效，**不是分布式限流或全局费用保护**。白名单不可省略；运营方仍需配置服务商配额和预算。返回对象丢弃图片、电话等未使用字段。
