# Map 卡片微缩与页头个性化

## 本轮按确认范围实施

- **仅缩短 Map 底部地点卡**：370 → 340rpx，内容区 300 → 270rpx，照片高度 245 → 215rpx。餐厅文字字号、地址、日期、收藏及两项地点操作保留，共享玻璃材质不变。
- **Me 原有统计卡和菜单行高度不变**：仍为 260rpx / 124rpx。菜单新增「个性化」，因此菜单总行数增加；底部内容沿用原滚动方式。

## 使用入口

**Me / 我的 → 个性化**，在原有可滚动 Sheet 中集中编辑：

| 页面 | 可编辑内容 |
|---|---|
| Home | 上行标题（原 Savor）、下行标题、副标题 |
| Map | 页头标题、副标题 |
| Add | 页头标题、副标题 |
| Us | 页头标题、副标题 |
| Me | 名称、签名；与原头像旁编辑入口共用 profile 字段 |

- 页面标题最多 24 字符、副标题 55；Home 上行 20；Me 名称 32。超长页头按原布局省略显示，编辑框内保留完整已保存文案。
- Home / Map / Add / Us 输入留空，使用当前应用语言的默认文案；自定义文字不翻译。Me 名称必填，签名可空。
- 每页有「恢复此页默认」。恢复和编辑都只修改草稿，点击底部「保存个性化设置」才生效；直接关闭不保存。
- 云列表/其他 store 更新不会覆盖当前正在输入的文案。
- 保存成功后同步刷新已加载页面；重启从原 `savor-diary-v1` 恢复。存储失败会显示错误并保留输入，不改动生效中的设置。
- 个性化**仅保存在本机**，无跨设备同步承诺；不新增云函数、数据库结构或环境配置。原照片、记忆、主题、语言和其他设置不受影响。

## 验证

`npm run verify:all`：**189/189 静态检查，58/58 mock 场景通过**。原验证保留；新测试覆盖输入清理/字符限制、语言与自定义文字分离、保存和重启、存储失败回滚、取消/逐页恢复、草稿抗刷新、Map 缩短及 Me 行高不变。原 UI baseline 未修改，授权变更另记批准哈希。

**未执行微信开发者工具、真机或线上 CloudBase 验证。** 建议微信端重点检查：

1. Map 地点卡两行地址信息、日期、收藏、照片及两项操作无重叠；长餐厅名仍省略显示。
2. Me → 个性化可滚动至 Me 字段和保存按钮，键盘弹出时可正常输入及保存。
3. 自定义中英混合标题，切换语言并重启，自定义内容不变；留空的页面随语言恢复默认。
4. 关闭未保存草稿后重新进入，旧内容不变；恢复默认后保存才生效。
5. 原 Me 名称/签名编辑入口与个性化入口互相反映修改，头像不丢失。

本轮未扩展其他真实统计、日期、地理元数据及云编辑同步事项。上一版云函数正确部署时，只需替换前端重新编译。
