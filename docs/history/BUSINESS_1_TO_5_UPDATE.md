## 1. 本地日期正确性 — 已实施

- `miniprogram/utils/localDate.js` 统一设备本地年月日、日历加减、周一为一周起点及相隔天数。
- 新建草稿、Add 日期上限、Sheet 日期上限、Us 在一起天数接入 helper；日期上限在页面再显示时刷新。
- 不再将 UTC 截断值用作「今天」。ISO UTC 仍用于导出/反馈等真实时间戳与纯日期合法性校验。
- 新资料不再预填「427 天前」；已有资料中的起始日期保留，天数按该日期计算，不从餐食数量推算。
- 回归覆盖东八区 23:59 / 00:01、闰日、周起点、纽约夏令时跨日。

## 2. 城市／国家地区一致性 — 已实施

### 规则

- 餐馆坐标仍来自原生腾讯 `wx.chooseLocation`，不再从固定城市下拉或同名餐馆推断新餐馆位置。
- 仅对可识别的地址前缀做保守解析：省份后的第一个地级市、直辖市，以及列出的港澳／台湾城市前缀。例如「江苏省苏州市太仓市…」取「苏州市」，不会把两个市拼接。
- 解析不确定则留空。Add 的选点卡下方可分别确认／修正城市和国家地区，标记为 `geoSource: user-confirmed`；未知地址不根据坐标臆造国家。
- 元数据以 `geoConfirmed` + `geoSource` 描述可信口径。该标记表示地址解析或用户确认，**不是腾讯认证 POI 身份**，也不保证用户选点本身正确。
- 选点地址与坐标一起保存；旧的 Paris/France 不能随新坐标继续沿用。仅填一项城市或国家地区时提示补全；两项均未知可暂存，但不计入城市统计。

### 旧记录处理

- 旧腾讯选点记录缺少新确认标记时，不再把旧城市／国家用于显示和统计，保留地址用于辨认；不擅自批量猜测所在地。
- Map「餐馆位置待确认」也包含元数据未确认的旧记录，可重新选点完成修复；未知格式可通过「餐食详情 → 编辑餐食」手动确认。
- 修正云记录走版本化修改队列；之后重新同步不会恢复旧城市。无需新增 WebService Key，不引入收费逆地理接口。
- 本环境未连接用户线上数据，因此**没有声称已经替用户批量修正全部旧记录**；修复入口、读写规则与迁移防护已实现。

## 3. 真实统计 selectors — 已实施

统一由 `memoryStats.js` 提供，不再叠加 12/5、48/17、72/28 等演示基数：

| 位置 | 口径 |
|---|---|
| Home 本周餐食／地点 | 本地日历本周一至今天，未来日期不计入本周 |
| Me 餐食／地点／收藏 | 全部真实可见记录；收藏仅 `saved`，不混入点赞 |
| Us | 仅 `shared` 的真实记录，非情侣账号间共享 |
| 周报柱图、Me 小折线 | 本周七个日历日的真实餐食数量；0 不再画成有高度的柱 |
| 旅程时间线 | 真实共享记录按日期排序，不再插入京都／哥本哈根等固定故事 |

统计按记录 ID 去重，排除原七条演示 ID、已删除／待删除记录；本机真实新增或导入的非演示记录也计入。地点以餐馆名 + 已确认选点的四位小数坐标去重，或以确认的城市／国家／地址组合去重；这是**日记内地点归并规则，不是全球唯一餐馆 POI 库**。坐标取点差异仍可能使同一餐厅被分成两处，后续可通过位置校准统一。城市 selector 仅计已确认的国家地区 + 城市组合。

演示样例继续用于明确标记的 Map 演示体验，不自动上传，也不计入真实统计。已有演示 ID 即便本机编辑，仍按演示处理；真实记录请从 Add 新建。

## 4. 旧业务字段与图片预览 — 已实施

- Add 新增独立的 **人均消费、菜系、菜品列表**；菜系是独立字段，不再借用 tags。菜品以逗号分隔输入、数组存储。
- 人均为数值，客户端及服务端拒绝负数、非数字及超过 1,000,000 的值；不擅自指定币种。
- 未评分在 Memory 中为 0，保存时不制造单评分。旧双人评分继续保留；只改备注等其他字段不会把旧均分写成一次新投票，更不会把单评分复制给两人。
- 最多 **9 张照片**；主图和缩略图可全屏预览，可移除任意缩略图。详情支持全屏预览与业务字段展示，无照片时标注占位图。
- 延续照片上传复用与草稿保护；不因替换一张图片就无条件删除可能仍被其他记录引用的本机文件。

## 5. 餐食编辑／删除／状态同步 — 已设计并实施

### 入口与行为

- **餐食详情 → 编辑餐食**：复用 Add 表单，可修改名称、备注、日期、位置、字段及图片。覆盖已有草稿前确认；尚未确认结果的请求不能被新编辑静默覆盖。
- **收藏／点赞／共享**：先将操作写入本机 outbox，再即时更新 UI，后台同步。
- **删除**：云记录使用 tombstone（逻辑删除）；本机先隐藏，待联网同步。服务端拒绝后续编辑复活该记录，旧 Add 请求重放也不能复活它。本机样例／仅本机导入数据仍只在本机处理。
- **Me → 同步状态**：查看待同步、错误及冲突；支持重试。冲突或明确拒绝可确认「以云端为准」，放弃该条本机待同步修改，再重新编辑。未知网络结果不能直接当作安全取消，需先重试确认。
- App 回到前台、Home 显示、网络恢复和手动重试都会触发同步；失败保留缓存与队列。

### 权限、并发与幂等

- `OPENID` 仅从云函数 `getWXContext()` 获取；查询及写入均限定 `createdBy`，不会因为 `shared` 标记开放给另一用户。
- 新增仍使用 owner-scoped 请求主键；修改增加 `revision`、`operationId` 和服务端操作 ID 记录。
- 用带 revision 的条件更新处理并发：两端同时修改时只接受一个，另一个成为显式冲突，不静默覆盖。
- 同一操作重试不会重复应用；本机串行操作仅在前一个得到确认后更新下一操作的版本；迟到的旧列表不能覆盖较新已确认修改。
- 新增 `update / flags / delete / get` action；旧 `setLocation` 保留兼容并参与版本条件写入。新客户端的位置修正使用幂等队列。
- 新记录／修改记录采用 schemaVersion 3；旧无 revision 记录按 0 兼容。原 `savor-diary-v1`、`savor-draft-v1` 保留，outbox 存在原日记键内。
- 原云记录上尚未同步的 `localChanges` 收藏／点赞／共享会一次性迁入队列；不上传七条样例。**历史版本的本机隐藏记录不会被自动升级为云端删除**，避免未经确认的数据破坏。

### 文件策略

- 本机清理把当前记录、草稿、待同步操作的旧／新照片都作为引用，保护离线重试及删除待确认期间的文件。
- 云端餐食删除／移除图片后，**不立即物理删除云文件**。文件可能被其他餐食复用，也可能属于未获确认的上传；保留比误删安全。
- 本轮没有全局孤立云文件回收器、情侣共享或跨账号资源授权。云文件保留会占用空间，后续如需要自动回收，应单独定义保留期、归属和全局引用检查。
