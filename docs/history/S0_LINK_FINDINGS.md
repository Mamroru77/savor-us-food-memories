### 如何解释失败

- 点评的 HTTP 500 是抓取工具返回的失败信息，不能据此确定是网站源站、访问环境还是其他环节造成。
- 美团页面只有“出现点问题，请稍后再试～／重新加载／错误码”，没有取得店名、地址、价格等可核验资料。
- 没有证据证明必须登录，也没有证据证明链接已失效。微信、系统浏览器、平台 App 的可达性仍待真机验证。
- 美团样例属于**外卖店铺**，不是已验证的堂食餐厅页。不可默认外卖分店与地图堂食 POI 是同一实体。
- 未尝试绕过登录、验证码、访问限制，也未接入非公开接口。

## 2. 对导入设计的约束

保持 Add 为统一入口，建议优先支持“粘贴完整分享文本（内含链接）”，将链接作为来源与可选补全线索，不将网页抓取成功作为生成候选的前置条件。

1. 处理 Markdown 链接和 `&amp;`，保留原始来源；不要对整段 URL 盲目反复解码。
2. 文案字段、网页字段与用户确认字段分开，缺失保持空值，不猜测城市 ID 对照、行政区或坐标。
3. 点评数字评分保留为平台参考评分，不通过星形数量推算；**不写入个人评分或两人评分**。
4. 平台人均价格仅供参考，**不当作这次实际消费自动保存**。
5. 美团两个样例只能先提取名称；地址待用户补充或腾讯地图搜索确认。即便名称含“太仓”，也不能据此自动确认坐标。
6. 用户确认具体分店、地址和腾讯地图位置之后才进入可保存草稿；不自动创建已吃过的 Memory，不制造用餐日期或到访统计。
7. 后续 Wishlist 接入时可以保存待去候选，但本轮不创建 Wishlist 或共享记录。
8. 未来如增加服务端 URL 补全，必须校验协议、精确域名及每一跳目标，阻断内网地址，限制超时、跳转次数和响应大小；不向任意输入 URL 转发凭证。本轮没有实现抓取服务。
